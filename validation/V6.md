# V6 measured: repeat-test scatter from NHTSA full-frontal pairs (6 of 8 pairs used)

Task t-20261121-183739 (fix round 2), 2026-11-21. Replaces the remembered V6 figures in `docs/STAGE6-M4-M5.md` with numbers measured from raw NHTSA data. Nothing here ran the simulator or touched test B's pulse (`validation/test-b.*`); the raw files under `reference/nhtsa-pairs/` were only read.

## Commands

From the Broadsword root (in this task's worktree the script path is `validation/v6_scatter.py` and the folder `../../../reference/nhtsa-pairs`; the output is identical):

```
python -I projects\crash-sim\validation\test_v6_scatter.py -v
python -I projects\crash-sim\validation\v6_scatter.py reference\nhtsa-pairs
```

The second command exits 0 and printed the block under "Full output" below, unedited (it was run as `broadsword.exe run crash-sim --task t-20261121-183739 -- python -I validation/v6_scatter.py ../../../reference/nhtsa-pairs`). The script re-checks every zip's sha256 against `reference/nhtsa-pairs/SOURCES.md` before using it and exits 2 on a mismatch; it passed for all 16 zips. The `files` lines in the output give, per test used, the zip sha256 (equal to the SOURCES.md value), the sha256 of the `.EV5` specification file inside the zip, and the sha256 of the channel file used.

## Method (what the script does)

- Reads each test's zip with `convert.py`'s EV5 and channel parsers and its axis/unit tables (G'S times 9.80665 to m/s^2, XG axis, time column checked against NFP and DELT, `NFP <= 0`, point count checked against NFP/NLP). `convert.py` is unchanged. Its `build()` is not used: it refuses titles not starting "NCAP - " and only knows the codes FLLR and FLRR.
- Metrics follow `docs/STAGE6-M4-M5.md` lines 81 to 84 (quoted in the script's docstring) and are ports of `src/pulse.rs`: CFC filter over the whole record (J211 phaseless 4-pole Butterworth); delta-V = minus the trapezoid integral of the CFC 180 acceleration over [0, 0.15 s] (includes rebound); peak = most negative CFC 60 value in the window and its time; OLC (65 mm free flight, 235 mm restraint) of the CFC 180 pulse with v0 = CLSSPD / 3.6. Window 0.15 s (`--pulse-window 0.15`, line 151). Time zero is the database's index 0.
- Pair difference: |a - b| / mean(a, b) for delta-V, peak and OLC; absolute milliseconds for time of peak. This is the difference between the two tests, not a coefficient of variation: for two tests the sample CV is that difference divided by sqrt(2).
- Median and max are over the counted pairs.

## Channel kind (fix round 2: what DSRR is)

The first version of this task treated the SENATT code DSRR as a right-rear seat crossmember, like SERR and FLRR, with no source. That was wrong. Source found, read 2026-11-21 (public, via the static.nhtsa.gov mirror; www-nrd.nhtsa.dot.gov returned HTTP 403 and was not retried): NHTSA Component Data Reference Guide (Version 4, June 1997), `https://static.nhtsa.gov/nhtsa/downloads/NRD/Research/Software/entree-for-windows/comdb-v4.pdf`, Appendix B "Codes", CMPNT table, page B-6. Its text (as extracted with pdftotext, the two columns interleaved) lists under "Doors: door sill (side rail below door)" the codes DSLF, DSLR, DSRF, DSRR against the descriptions LEFT FRONT, LEFT REAR, RIGHT FRONT, RIGHT REAR; under "Floorpan" FLLF, FLLR, FLRF, FLRR (same four descriptions); under "Seats ... bucket (reclining)" SELF, SELR, SECF, SECR, SERF, SERR against LEFT FRONT, LEFT REAR, CENTER FRONT, CENTER REAR, RIGHT FRONT, RIGHT REAR. The guide also says (Appendix B, CMPNT) "If the component type (CMPTYP) is a vehicle, then the CMPNT field will denote a specific location on the vehicle, and the SENATT field will denote a general location", and defines SENATT as "the actual physical attachment point of the sensor". So the guide's code list is for the component field and is applied here to SENATT by that statement and by the instrument rows themselves (NCAP 2010 FLRR rows say "RIGHT REAR SEAT CROSSMEMBER X"; Volume I of the Test Reference Guide, Version 5, Nov 2014, `https://libraryarchives.metro.net/DPGTL/nhsta-national-highway-traffic-safety-administration/2001-nhsta-test-reference-guide-version-5-volume-1-vehicle-tests-2014-revision.pdf`, read 2026-11-21, shows DSRF and DSRR X/Y/Z accelerometers as "ACCEL. LOCATION #1" and "#2" next to DSLR, DSLF, FLRR in its example instrument list). That Volume I has no SENATT code table of its own. Limit: the table is from the 1997 guide; I did not find a later table.

Result: DSRR is the right-rear door sill (the side rail below the door), a different structure from a seat (SERR) or floorpan (FLRR) accelerometer, and no file in `reference/nhtsa-pairs/` (all DSRR channels say "NO COMMENTS"; the EV5 files hold no code table) says otherwise. Therefore:

- A pair is only used if both tests have a channel of the same kind: right-rear seat/floor crossmember X (SERR or FLRR), else left-rear (SELR or FLLR), else right-rear door sill X (DSRR), else left-rear door sill (DSLR). `RIGHT_REAR` and `LEFT_REAR` in the script no longer contain DSRR or DSLR.
- Pair 1 (6258/6271): neither test has a seat or floor X channel; both have DSRR (curve 90). It is used on the door sill channel, labelled "right rear door sill X (DSRR)" in the output.
- Pair 6 (6736 DSRR/DSLR vs 6766 SELR/SERR) and pair 7 (6642 FLLR/FLRR vs 6643 DSLR/DSRR): no common kind, so both are EXCLUDED. The script prints the vehicle-1 global X accelerometer codes of each test beside the exclusion (output below). The only X accelerometer codes common to both tests are ENGN, BRCL and BRCR (engine, brake calipers), which are not the brief's channel kind and were not used.
- Pairs 4 (FLRR vs SERR) and 5 (SERR vs FLRR) compare a floorpan crossmember with a seat accelerometer: the 2010 NCAP FLRR comment calls it the "RIGHT REAR SEAT CROSSMEMBER", and SERR rows carry comments "RIGHT REAR", but the codes are not equal. They stay in the main statistics (kind "seat/floor") and the script also prints the statistics over the pairs whose SENATT code is the same in both tests (pairs 1, 2, 3, 8, `counted_same_senatt_code`). Both sets are reported.
- The vehicle CG channel (VECG) exists only in 5036, 5061 and 5073 and was not needed. Curve numbers and codes are in the output rows ("channel curve N CODE").

## Which pairs counted, and why

Rule (in `v6_scatter.py`, printed in the output): same model year, mass within 5% (the brief's number), and VEHICLE fields 13 and 14 within 5%. Fields 13 and 14 are read as the two long dimensions in mm (for example the CTS pair 2885/4825 and 2880/4820); the Guide's field names for them were not read here. Body-style code and make/model codes are printed for every pair but are not part of the rule.

All 6 pairs with a common channel kind counted (1, 2, 3, 4, 5, 8); pairs 6 and 7 are excluded for the channel reason above, not for vehicle differences. Pair 3 (5061 body PU, 4240 body EX; model codes 44 and 43): mass differs 2.5%, the two dimensions 0.3%, so the same truck structure by that rule; it is the only pair that sets the peak maximum (17.60%), so the substitute rule matters there: the brief said "body and mass the same", and here body codes differ. Pair 8 (3915 body EX, 5073 body 4P; same model code 24): mass 0.9%, dimensions 0.1%. The script also prints the summary for the pairs with identical body codes (1, 2, 4, 5): it drops pairs 3 and 8, so its peak maximum is 10.28% and its other figures are in the output.

## Limits of this measurement

- 6 pairs (4 with identical SENATT codes), so a maximum over so few values is itself noisy; pairs differ in era, barrier (NCAP rigid barrier, or the load-cell barrier used in the older Trailblazer, Ram and Tundra second tests) and sample rate (20 kHz, 12.5 kHz, 10 kHz). Pairs 2, 3 and 8 mix an NCAP test with a flat-load-cell-barrier test.
- One channel per test, not the vehicle CG; pair 1 uses a door sill channel.
- Three different vehicles (6258, 6724, 6736, all 100 us records) peak at exactly 54.9 ms. This was seen by the reviewer and is not investigated here; 6736 is now excluded, 6258 (pair 1) and 6724 (pair 4) remain.
- Time of peak is the time of the global CFC 60 minimum inside the window, so a pulse with two similar peaks can flip between them.
